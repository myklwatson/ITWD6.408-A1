JSON Rules

Important Rules that must be adhered to in order to create a valid JSON data:

Data Types

JSON supports six data types: strings, numbers, objects, arrays, booleans, and null. Every value in a JSON document must be one of these types.

{
  "name": "Michael",       // string
  "age": 37,                // number
  "isStudent": true,        // boolean
  "address": { "town": "Hastings" }, // object
  "hobbies": ["Photography", "Gaming"],   // array
  "notes": null             // null
}
Object Structure

Objects are wrapped in curly braces { } and contain key-value pairs separated by commas. Keys and values are separated by a colon.

{
  "fname": "Michael",
  "lname": "Watson",
  "town": "Hastings"
}
Array Structure

Arrays are wrapped in square brackets [ ] and hold an ordered list of values, separated by commas. Values can be of any valid JSON type.

{
  "phoneType": ["iOS", "Android"],
  "marks": [85, 92, 78]
}
Key Rules

Keys must always be strings wrapped in double quotes. Single quotes and unquoted keys are not valid JSON syntax.

// Valid
{ "fname": "Michael" }

// Invalid
{ fname: "Michael" }
{ 'fname': "Michael" }
Strings

String values must be wrapped in double quotes, not single quotes. Special characters need to be escaped using a backslash.

{
  "quote": "She said \"hello\"",
  "path": "C:\\Users\\Michael"
}
No Trailing Commas

JSON does not allow a trailing comma after the last item in an object or array. Doing so will cause a parsing error.

// Valid
{ "a": 1, "b": 2 }

// Invalid
{ "a": 1, "b": 2, }
